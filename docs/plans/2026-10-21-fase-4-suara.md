# Fase 4 — Voice & Alignment: Rencana Implementasi

> **Untuk agen pelaksana:** Wajib memakai sub-skill: gunakan superpowers:subagent-driven-development (disarankan) atau superpowers:executing-plans untuk menjalankan rencana ini per task. Langkah memakai kotak centang (`- [ ]`) untuk pelacakan. Gaya UI mengikuti antislop (identitas Fase 1-3) dan komentar kode mengikuti antislop-code.

**Tujuan:** Setiap scene dari script yang disetujui punya klip suara asli tersimpan sebagai aset (bisa diputar dari UI) dan timing kata tersimpan (dari provider, Whisper, atau proporsional), sementara kecepatan bicara terukur memperbarui kalibrasi yang dipakai estimasi durasi.

**Arsitektur:** Tabel `asset` (semua jenis, versi per project/scene/kind, `is_selected` tunggal) + `voice_calibration` (rata-rata bergerak per provider+suara). Job `voice` per scene: sanitasi teks → cache `input_hash` → sintesis (router suara; fake / muse_cli) → simpan klip → ffprobe + silencedetect (trim dicatat, file asli utuh) → kalibrasi → timestamp provider menjadi aset `word_timings`, selain itu enqueue `align`. Job `align`: WhisperAligner (faster-whisper) dengan pencocokan kata script; gagal/ratio rendah → ProportionalAligner; job tidak pernah gagal karena Whisper. Reconcile pasca-Gerbang B mengantrekan `voice` untuk scene yang aset terpilihnya tidak cocok dengan hash keadaan sekarang.

**Stack teknologi:** yang sudah ada + `faster-whisper` (sudah terpasang di venv VM ini; ditambahkan ke pyproject), `ffprobe`/`ffmpeg` sistem, CLI `tts` VM untuk adapter `muse_cli`.

## Keputusan lingkup fase ini

1. **Satu migrasi `0004`** memuat kolom suara project, `asset`, dan `voice_calibration`. FK `asset.scene_id`/`generation_job.scene_id` yang disebut spec "sejak migrasi 0005" tidak ditegakkan sebagai constraint sqlite (konsisten dengan kolom relasi lain di repo ini yang bertipe String polos); integritas dijaga kode.
2. **Alokasi versi aset** = max+1 di dalam transaksi tulis (pola `save_draft`); balapan dua job aset untuk scene yang sama dicegah antrean resource per provider + dedup job aktif per scene, bukan lock DB.
3. **Whisper diuji lewat transcriber suntikan.** `WhisperAligner` menerima fungsi transkripsi yang bisa diganti di tes; tes unit tidak mengunduh model. Satu smoke test manual di Task 9 (di luar suite) membuktikan jalur asli dengan model `tiny` lewat env.
4. **Trim memakai ffmpeg `silencedetect`** (noise `-45dB`, durasi minimum hening 0,25 dtk) terhadap file klip yang tersimpan; hasil parse menjadi `data.trim`. Bila ffmpeg gagal, trim kosong dan job tetap lanjut (kalibrasi memakai durasi penuh).
5. **Suara bawaan project**: `voice_id` kosong berarti pakai `default_voice` provider (quirks) atau `"default"`. `expected_voice(session, project)` di `ProviderRouter`: pin project bila ada, selain itu kandidat suara pertama + voice defaultnya. Inilah yang dipakai reconcile, handler, dan `checks_for` untuk wps.
6. **Cache voice** mengikuti §2.4: sebelum memanggil provider, cari aset `voice_clip` di project sama dengan `input_hash` sama; ketemu dan job tidak `force` → buat baris aset baru untuk scene ini menunjuk `storage_key` yang sama (bila scene berbeda) atau pakai baris yang ada (scene sama), jadikan terpilih, lanjut ke langkah timestamp/align yang sama. Lewati pembuatan baris duplikat bila aset terpilih scene ini sudah persis baris itu.
7. **Daftar suara adapter**: fake → satu suara `fake-1` ("Suara Fake (2,5 kata/dtk)"); muse_cli → suara bawaan CLI `avocado_v2:MAI_03` ditambah daftar pendek yang diketahui CLI (`--voice` bebas; UI tetap menyediakan input teks). Adapter lain belum ada untuk suara di fase ini.
